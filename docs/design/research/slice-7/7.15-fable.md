## 1. Soundness: the forgery gates, one by one

The device shape keeps format 35's ledgers (`MemoryChip`,
`RegisterMemoryChip`) and the CPU's execution relation untouched and
replaces the producers at their ends. So each gate reduces to: does the
device producer put the right tuple in, and does the ledger's existing
gadget then force the run to respect it. I checked both halves for each.

**1a. The memory ledger's gadget is what makes the boundary-free shape
consistent** (`chips/memory.rs:247-345`). The ledger is sorted by `(address,
2·ts + is_write)` through the two 16-bit halves `a_lo = l0 + 256·l1`, `a_hi
= l2 + 256·l3`: on a real→real transition exactly one of {same, lo-advance,
hi-advance}, `same ⇒ both halves equal`, an advance strictly increasing with
a 28-bit witness, so **every address's rows are contiguous and there is one
group per address** (two rows with equal halves cannot be an advance: the
advance's `diff − 1` would be `−1`). The group's first row must be a `ts = 0`
write (`:335-341`), its last a closing read (`:343-344`), and within the
group `prev_value_next = value` and `read ⇒ value = prev_value`. Nothing of
this changed; what changed is who produces the `ts = 0` write and the
closing read. In format 35 it is MemoryPageChip for every byte of a listed
page; here it is DeviceMemoryChip for every byte the run touches, with the
same tuple shapes (`device_memory.rs:194-217` against
`memory_page.rs:359-391`: `(addr, initial, 0, 1, 2·permission)` and
`(addr, last, closing_ts, 0, 1)`). Consequences, each checked:
- **A touched byte with no DeviceMemoryChip row** has a group with no
  `ts = 0` write → group-start violation; one with a row but no access is a
  two-row group, harmless. **Two rows for one address** are harmless too:
  both `ts = 0` writes are constrained to the same initial (the table's or
  zero) and both closing reads chain in one group, so a duplicated first
  touch cannot stage a stale read. Worth one sentence in the module doc.
- **The closing timestamp is a free column** (`ClosingTs`) and that is fine:
  the group-end rule forces the closing read to be the group's last row,
  the key order then forces every access of the byte before it, whatever
  value the prover chooses; a closing read placed early leaves a non-closing
  last row. The module doc says exactly this (`device_memory.rs:20-22`).

**1b. A first touch of a data byte other than the table's.** On a real row
exactly one region selector is 1 (`selected = is_real`, each boolean,
`:165-181`); `initial` is looked up in `DataTable` with multiplicity
`data_region` (`:218-220`), and `zero_region · initial = 0` (`:192`). The
table is preprocessed `(address, byte)` (`data_table.rs`), so the `ts = 0`
write's value is the table's or zero, and the ledger chain starts from it.
The table covers each data region exactly: `DeviceLayout::of_program`
(`device.rs:179-216`) takes the read-only region as `pages(ro.base,
ro.size)` with `ro.size = page_round(len)` (`pvm/program/src/lib.rs:120`)
and pads the table to the same page count; the read-write data region is
`[rw.first, rw.first + ⌈len/page⌉)` and the heap the rest. Gate:
`a_data_byte_other_than_the_tables_is_refused` (`Error::Logup`). Correct.

**1c. A nonzero first touch of stack or heap.** `zero_region · initial = 0`
with `zero_region` the sum of the non-data selectors. The forged run
(`init_copy` on the stack buffer the witness overwrites, and on the heap
word the kernel writes) carries the forged byte as `initial`
(`DeviceRun::of` reads the entering image, `device.rs:291-319`), breaks the
constraint, and the forced proof fails `OodsNotMatching`. Correct, and the
test asserts the stack pointer so the forged byte is really under the
buffer.

**1d. A touch outside the regions.** A row with no region has `selected =
0 ≠ is_real`; the region bounds are preprocessed (`RegionFirst`,
`RegionEnd`, part of the root) and the page is placed by two 20-bit
distances `page − first` and `end − 1 − page` (`:184-189`), exact because
every page index is below `2^20` and a wrapped negative is above it. So an
address outside every region has no first touch and its group cannot
start. `install` refuses overlapping regions (`recair/src/masked/device.rs:133`),
so the selected region, hence the permission and the first-touch rule, is
a function of the address. Gate: `a_touch_outside_the_regions_is_refused`
(a page the machine maps between the data regions). Correct.

**1e. A write to a read-only page.** The `ts = 0` write carries
`2·permission` with `permission = 1` for the read-only data and the
argument window, `2` otherwise (`:197-202`, `region::READABLE_ONLY`); the
ledger's start row takes it as `Readable`/`Writable`, holds them along the
group and refuses `is_write · (1 − is_start) · (1 − writable)`
(`memory.rs:346-388`). No producer emits permission 0, so no unreadable
group exists in a device run. Gate: `a_write_to_a_read_only_page_is_refused`
(the machine's page made writable, the kernel storing into its read-only
data). Correct. The Poseidon2 chip's output writes go through the same
ledger rows, so an output pointer into read-only data is refused the same
way (live: `write_bytes_checked` fails and the call traps).

**1f. A second segment.** DeviceBoundaryChip produces the entry
`(ts 1, pc 0)` and consumes the halt `(final_ts, HALT_PC)` in the execution
relation (`device_boundary.rs:156-170`), the CPU's rows consuming `(ts,
pc)` and producing `(ts + 1, next_pc)` as before
(`cpu/constraints/control.rs:230-242`); the registers enter at the layout's
preprocessed values (`InitialValue`) at `ts = 0` and close at `final_ts`,
one column equal across the thirteen rows (`IsChained`). So the run starts
at the program's entry with the program's registers, ends at the halt, and
is one segment; a run cut at `2^16` steps or ending in a trap produces no
`(ts, HALT_PC)` and is refused. Gate: `a_second_segment_is_refused` (the
run from its sixth step, its registers and memory as the first five left
them). It passes, but its assertion is `is_err()` on whichever error comes
(L3).

**1g. A Poseidon2 output not the permutation's.** The permutation is
`p2`'s arithmetic over 142 S-box pairs, `a = y²`, `out = a²·y`, two
constraints each, ungated (`poseidon2.rs:195-238`); the output words are
bound by `is_real · (word(output bytes) − state_j) = 0` (`:311-315`), and
each output word is made canonical: every output byte in `Range256`, the
top byte plus 128 in `Range256`, and `(Σ bytes − 892) · inv = 1` (`:316-325`,
`:359-371`). A word below `2^31` with byte sum `3·255 + 127` is `p` and only
`p`, so the bytes are the one encoding of a field element: a prover cannot
write `0` as `p`. Gate: `a_poseidon2_output_not_the_permutations_is_refused`
(a bit flipped; `OodsNotMatching`). The non-canonical case (`0` written as
`p`) has no test (L3).

**1h. An input word ≥ p, p included.** The same two checks on the input's
top byte and byte sum (`:316-325`, `:378-387`); the lower bytes are bytes
because they are ledger values and every writer range-checks what it writes
(the CPU's `result_bytes`, the witness input, the Poseidon2 output, the
first touches: the table's bytes or zero). Gates: `p` itself (the inverse
has no value: `OodsNotMatching`) and `2^31 + 5` (the top byte plus 128 is
256: `Error::Logup`), each with the witness bytes, the call's input and its
output changed together so that only the range is wrong. Correct. The
tracer agrees with the chip: `Poseidon2Op::compress` refuses a word `≥ p`
(`core/tracing.rs:49-66`) and the call traps.

**1i. A call without its row.** `CpuP2Chip` produces `(ts, φ7, φ8)` in
`Poseidon2Call` with multiplicity `IsP2Ecall`, and `IsP2Ecall` is tied to
the instruction: the host-call continuation requires `is_blake + is_witness
+ is_p2 = acknowledged` and `100·is_blake + 101·is_witness + 102·is_p2 =
acknowledged · dispatch` with `dispatch` preprocessed in ProgramMemory
(`host_call.rs:46-62`); the chip consumes one tuple a real row
(`poseidon2.rs:332`). So a call has its row and a row its call. The call's
row writes no register: `ResultIsReg` is bound to the instruction's flag
byte less `IsWitnessEcall` (`cpu/constraints/program.rs:96-101`), 0 for an
`ecalli`, and the CPU makes no memory access on it; the chip's 64 reads and
32 writes at the call's timestamp are the call's whole effect, reads
before writes at one `(addr, ts)` as the ledger orders them. Gate:
`a_call_without_its_row_is_refused` (`Error::Logup`). Correct.

**1j. The addresses `ptr + i` and their carries** (`poseidon2.rs:140-169`,
`:285-305`). The carries `c_i` and the increment `(ptr >> 8) + 1` are
prover-chosen booleans and limbs, bounded only on real rows. I checked what
a wrong choice buys: nothing. With `inc` exact (the three increment
constraints) the four limbs always sum to the integer `ptr + i` whatever
`c_i`, so the ledger's halves either equal the true address's (the row
joins the true group and reads the true byte) or leave `[0, 2^16)` as
integers (a half negative or `≥ 2^16`), in which case the row can share no
started group (a `ts = 0` write's halves are byte-composed) and cannot
start one (it is not a `ts = 0` write). The module doc's argument, "an
address whose limbs are not bytes, which no first touch produces, so its
group has no start", is the second case only; the first case is the common
one and is sound for a different reason. BLAKE2b's chip carries the same
sentence. L1.

**1k. The io-hash output binding.** DeviceBoundaryChip consumes
`(r, final_value)` for `r ∈ 9..12` in `IoHash` (`device_boundary.rs:172-176`),
`final_value` being the register's closing-read value and so the ledger's
last value; DeviceIoChip produces `(r, value)` on four preprocessed rows
and its claimed sum is **the one public sum** of the set
(`masked/mod.rs`, `Device::public_sums`), recomputed by the verifier from
the proof's 32 io bytes (`io_claimed_sum`, `device_bound_sums`,
`verify_device`). The io bytes are mixed as public values after the main
root and before the relations are drawn, so the prover commits the
`Value` column and the io before `(α, z)`; equal sums at a random point
imply the four tuples are the io's with probability about `8/p^4` off.
Gates: `the_io_hash_is_bound` (another io: `InteractionPow | Logup`; a
forced proof blinding DeviceIoChip's sum: `Logup`),
`the_io_hash_is_the_one_public_sum`, and the right-guess leakage gate
(§2). Correct.

**1l. The program id's derivation at install.** `install`
(`recair/src/masked/device.rs:122-163`) takes the kernel alone: the layout
from the blob, the chips from the code (`device_chips_of_code`: every
opcode's chips and each `ecalli`'s precompile, so a path a run skips is
covered), the floors from the format, the preprocessed root from
`device_preprocessed` over a side note with no run. Every preprocessed
column the device chips add is the program's: the region bounds, the data
table, the entry registers; the code and dispatch ids in ProgramMemory as
before. The verifier takes **nothing of the program from the proof**: the
format and the log sizes in the statement header, `[VOS/DEV1, active]`
mixed after it (`MaskedFormat::program`, `final-verifier/src/masked.rs:382-384`),
the root as `Claim.circuit`. Gates: another program's chips or root
refused (`the_program_is_mixed_into_the_transcript`, `Error::Circuit`), a
chip set not the code's and a log size under its floor refused at install.
This closes the 7.14 review's 2e (the transcript now mixes the active set)
and M1 (the root is mandatory on the device path, and the honest-root
acceptance is every device gate). Correct.

**1m. The pinned shape.** `masked_device_trace` with `DeviceSizes::Pinned`
generates each chip at least its pinned size and refuses one above it
(`ProvingError::Shape`, `masked/trace.rs`); the gates
`a_run_past_the_programs_shape_is_refused` (a 16-byte reference, a
1,000-byte run) and `an_unused_chip_proves_at_its_pinned_size` (a
multiplication after the halt, all rows padding) cover both sides. This is
the 7.14 review's 1d.

**1n. The shared CPU and format 35.** `CpuChip`'s constraints are
`constraints_of(.., None)`, byte for byte; `CpuP2Chip` adds the selector
column and three fractions after format 35's (`cpu/mod.rs`,
`interaction/mod.rs`). The fixtures pass and the constants are unchanged.
One caveat: `proof_precompile_dispatch_id(0x402) = 102` is now committed by
ProgramMemory under every format, so a **node** kernel containing
`ecalli 0x402` has a different program-memory root than before this
branch. Under format 35 such a kernel was and stays unprovable past the
call (the continuation cannot select 102 without the selector, so the run
ends there), and pin H says `derive` admits the call in device kernels
alone, so no admitted node program is affected; but "format 35 byte for
byte" is true for kernels without the call, and the record should say so
(L2).

## 2. Zero knowledge under masking

**2a. What is public, and that it is only the statement.** The transcript
mixes the format, the log sizes, the tag and chip mask, the preprocessed
root and the io bytes: all the program's or the statement's. The claimed
sums: DeviceIoChip's unblinded, a deterministic function of the io and the
drawn relations; every other blinded with `Σ b = 0` (7.14's 1a/1b argument
carries over, the public set being smaller). The entry state is
**preprocessed** (the layout's registers, pc 0, ts 1) rather than a public
value, and the halt's registers and timestamp are masked columns
(`FinalValue`, `FinalTs`) whose only relation entries are blinded: so the
step count and every register but φ9..12 at the halt are hidden. This is
the right answer to pin J's gap the record names ("the plan was off": the
node's boundary chips would publish the whole boundary), and it is what
lets the device shape have **two witnesses under equal public values**,
which the 7.14 review asked 7.15's leakage gates to cover (M3).

**2b. The shape is the program's, so the two 7.14 qualifications are
closed.** `active` and `log_sizes` come from `install`, the prover pads to
them and refuses above them; `the_shape_is_the_programs_and_the_coins` is
therefore now a property of the prover, not of the kernels, and
`the_program_is_the_kernels` checks that two witnesses give one shape at
install. The install's reference run is public data (its sizes), and a
kernel that is not branch-free is refused for a larger witness rather than
proved at another shape.

**2c. Per-component `h`.** DeviceBoundaryChip has a `|O| = 2` column
(`FinalTs`, `mask_next_row`), DeviceMemoryChip, DataTableChip and
DeviceIoChip have `|O| = 1` main columns and their interaction running sums
read the previous row, so `mask_rows` gives each the format's `h` by its
widest offsets; the `|O| = 1` halving applies to no device chip in
practice. The heavy gate asserts `2·revealed ≤ h` at both device
parameter sets and R1 in one attempt; the record's measured `r1_rows` (137
at 43 queries, 266 at 86) are under `h/2` (256, 512).

**2d. The leakage gates** (`tests/device/leakage.rs`) are slice 6's seven
honestly adapted and, this time, with no deviation: witness
indistinguishability and uniformity over every published field but
DeviceIoChip's sum, hidden state (the 64 witness bytes and the 32 output
bytes, eight at a time), fresh openings (two proofs of one run; two
witnesses from one seed), the right guess reproducing the public sum alone
and the total, one shape. The right-guess gate reconstructs the relations
from the device transcript exactly as the verifier replays it (the header,
the program words, both roots, the io, the interaction PoW), which also
pins the mixing order against the verifier's (`replay`). Sufficient for the
step; the medium-N run is `test-proof`'s and I did not re-run it.

**2e. Nothing else of the run reaches the proof.** The data table's
multiplicities, the touched bytes' count and values, the Poseidon2 rows
(the padding rows hold the permutation of zero, committed masked), the CPU
rows: all main or interaction columns under the mask. `DeviceProof.io` is
the statement.

## Findings by severity

**Low**

## Verdict

**Accept.** The boundary-free shape is sound because the ledger's gadget
does the work and the device producers put the right tuples at its ends;
the Poseidon2 chip's range checks make the call's range the chip's and its
output encoding unique; the call is bound to its row through the committed
dispatch; the io-hash is the one public sum, recomputed by the verifier;
the program is the install's and the transcript's, the shape pinned. Fold
L1 and L2 before the merge if cheap; L3 and L4 at will.
