# 7.10b the node API and the gateway: the brief's review

Branch `s7/7.10b` at `50ef973c`, `docs/design/node-api.md`, read before any
code against `slice-7-mobile.md` §7.10b, §7.11 and pin I,
`identity-and-authority.md` §5–§7, S40, S41, S46, S49 and S50, and the code
the brief maps: `node/host/src/{ingress,http,tls,dispatch}.rs`,
`node/host/src/node/api.rs`, `node/host/src/client/*.rs`,
`agent/wire/src/ingress.rs`, `pvm/codec`, `node/net/src/{lib,tls}.rs` and
`node/net/src/quic/*`, `tools/scale/src/{collect,nodes}.rs` and
`tools/scale/src/engine/pool.rs`, and s4's `server/src/{server,auth,builder}.rs`.
Read-only; nothing built.

**Verdict: fix-then-implement.** The authority model is right and the frame
grammar is safe as a reader's contract: every check precedes any allocation,
the limits are derived correctly from today's, and nothing that reaches the
socket, the QUIC port or the `vos-api` subsystem gains more than relaying
once C5 lands. Eight gaps in the specification must close in the brief
before C1 (M1–M8); none is a rework. The largest: the `Operated` envelope
does not name its node, so the gateway cannot do the one routing rule the
brief gives it; the operator reads as specified break `vos-scale`'s
collector at T3's agent count; and the node's HTTP would depend on the
gateway crate until C10.

## 1. The frame grammar

**1a. Order of checks, safe.** `length < header rest → Truncated`, the kind
from two bytes, the relay set, `Oversize { limit }` from the header, then
the body read to `length` and `decode_exact` (`node-api.md:71-82`). Nothing
is allocated before the limit check, as `vos-net` does today
(`node/net/src/quic/receive.rs:104-112`); a 4 GiB `length` on a known kind
costs a header. A body that fails to decode is the kind's own `Malformed`,
as `ingress.rs:102-104` does now. Two holes in the table, not the order:
`0xffff` is in the kind table (`:150`) and must be `UnknownKind` as a
request, and the rule "an answer repeats the request's kind" (`:64-66`)
contradicts the frame error's kind (L1). An `AgentInfo` or `Schema` body
that is under its limit but does not decode (three bytes) has no stated
answer; `None`, as HTTP's non-`u32` id is an empty 404 today
(`ingress.rs:173-176`) (L2).

**1b. Close behaviour: one rule too many.** "After a frame error the node
or relay writes it, then closes the stream or the connection" (`:104-108`)
is right for the four framing errors, which are a client's fault or a
framing the reader can no longer trust. It is wrong for `Unavailable`
(`:96-97`): the gateway's upstream failed, the channel's framing is intact,
and the rule drops the other 15 requests in flight on a `vos-api` channel,
which is 7.13's path refresh (`slice-7-mobile.md:1056-1061`). `Unavailable`
is answered under its id and the channel stays open (M7).

**1c. Ids and multiplexing.** Client-owned ids, no table at the node, id 0
for an error the node cannot tie (`:67-70`): right and cheap. The gateway
keeps the only table (16 a channel). Out-of-order answers with whole-frame
writes (`:109-116`) are the HTTP pipelining the node never had; fine.

**1d. Resource exhaustion.** `api_connections` per transport, 256 in flight
per socket connection with the reader stopping past it, QUIC's
`max_concurrent_bidi_streams` (`:277-280`), the 60 s frame deadline and
QUIC's 30 s idle (`:117-120`), the nonce store's 65,536 (`:237`): bounded
on every axis the node sees. Two numbers are wrong for S50, though: 256 in
flight on one socket connection is T1's whole rate at its p99 (5,000/s ×
50 ms ≈ 250, `slice-7-mobile.md:783`), and the QUIC bidi cap is unstated;
a co-located gateway on one connection, or a driver on "one QUIC connection
a node" (`:386-387`), would measure the API's cap, not the node (M5). The
socket's in-order reading means one slow frame stalls the connection for
up to 60 s (`:110-112`): acceptable for a co-located gateway (its own
fault), say so (L8). The nonce store's "a listed key flooding it harms only
its own operator" (`:238`) is false of one shared table (L3, folded into
M3). Slowloris on the gateway: `http.rs`'s deadline and 16 KiB head move
with it, s4's `ServerLimits` bounds connections and the handshake before
authentication (`s4 server/src/builder.rs:54-62`); the `vos-api` channel
needs the same 60 s per frame and s4's no-await `data` rule
(`server/src/server.rs:34-54, 529-551`): the hook's input queue must
`try_send` and close the connection when full, as s4's does (L8).

**1e. Confusion between transports.** Different UDP ports, ALPN `vos-api/1`
against the peers' `vos/1`, raw keys both ways, no resumption (`:262-269`):
a peer's frame cannot reach the API endpoint, nor the reverse. The API's
little-endian length against `vos-net`'s big-endian one
(`quic/receive.rs:109`) is a second difference worth one line (L7). A
client that uses the stream header over QUIC puts eight id bytes into the
body: `Oversize` on the empty kinds, `Malformed` on the rest, and a signed
body that happens to decode is still bound by its signature. Harmless.

**1f. The limits** (`:171-181`): 69,636 = 69,632 + 4; 69,760 = 69,632 + 4 +
124 (`Operated`'s 32 + 16 + 8 + 4 + 64); 67,113,088 = `MAX_ELF` + 4,096 +
4 + 124; 1,642,496 = 1.5 MiB + 65,536 + 4,096 with the HTTP limit 4 less.
All check against `cap::REQUEST` (`agent/wire/src/abi/cap.rs:9`) and
`MAX_ELF` (`pvm/compiler/src/derive.rs:99`). M1 adds 32 to every operator
kind.

## 2. Authority

**2a. Nothing beyond relaying, once C5 lands.** The socket's file mode and
a `gateways` key admit frames; each is a signed call, query or workflow
read the node verifies (`ingress.rs:379-409`), a proof (7.11), an unsigned
public read (`NodeKey`, `AgentInfo`, `Schema`, `Time`, all served unsigned
over HTTP today), or an `Operated` the node verifies. The `vos-api`
subsystem relays the read set only and refuses the rest before reading a
body (`:344-347`). `app.key` (`:351-357`) is an ordinary client key whose
calls are "any caller" methods bounded by an invitation naming the digest
(`identity-and-authority.md` §6, `claim`): no authority a fresh key lacks,
and rightly apart from `gateway.key`, which is transport admission. The
interim (`:244-249`) is the decided S46 and is closed by C5 before the
gateway exists (C7), so no gateway ever meets a bare operator kind. Right.

**2b. The `Operated` envelope** (`:210-225`). Domain `vos/operator/1`,
distinct from `vos/call/1`, `vos/query/1` and `vos/workflow/1`, so a key
used both as a client and an operator cannot have a call replayed as an
operator request; the node id and the kind are in the signed bytes, so a
request is good at one node for one kind; `expires_ms` within 120 s by the
node's clock, `Expiry { now }` to resync, as `StaleQuery` does. Sound. But
the envelope itself carries no `node`, and the gateway's routing rule is
"the one node it is signed for, never redirected" (`:329-331`): it cannot
know which. Add `node: NodeId` to the envelope, checked before the
signature (M1); test 7's "signed for another node" then has a refusal of
its own instead of a `BadSignature` after a full verify.

**2c. Replay, across restarts and in flight.** Durable nonces (Q4, right)
close the restart case only if the row is synced before the command runs;
and the check order "(key, nonce) not recorded … then recorded"
(`:231-232`) sits after the `offload` await of the signature, so two
copies of one request in flight on the multiplexed socket both pass the
check. One atomic insert-if-absent on the node's thread, synced, then the
command (M4). The brief's "written before the command runs" is the intent;
the text must make it one step.

**2d. `local_operator` and `operator.key`** (`:240-243`). Equivalent to
`admin.token` (0600, `node/open.rs:426-437`) in trust; right to replace it.
The node reads the secret at every start to list its public key; write
`operator.pub` beside it and read only that after the first start (L4).

**2e. Operator reads with a nonce each** (`:164`, Q7). The protection a
nonce buys a read is nothing (a replayed `Stats` discloses what the first
did, within 120 s, to whoever already holds it), and the cost is real:
`vos-scale`'s collector polls `Stats` and `Status` of every placed agent
on every node every interval (`tools/scale/src/collect.rs:49-80`); at T3's
10^4 agents (`slice-7-mobile.md:785`) that is more than 65,536 nonces a
node inside two intervals, then `Busy` for every operator. Sign the reads,
record no nonce for them (M3).

## 3. Fidelity

**3a. The route table moved whole** (`:309-320`) keeps the statuses
(`ingress.rs:65-96`), the path parsing, the 411/413/431/100 behaviour of
`http.rs:246-299`, and the install limit by path suffix even on unknown
paths (`http.rs:255-259`), so test 1 can hold on every route but the
operator routes. Note `GET` bodies are read and limit-checked today, not
ignored (`http.rs:250-262`): "ignored" must mean read, counted against the
limit, then unused.

**3b. The operator routes are not byte for byte, and the brief under-states
it** (`:316-319`, Q2). (i) `GET /stats` and `GET /agents/{a}/status` would
carry the envelope in a GET body, against both HTTP practice and the
brief's own "GET bodies ignored"; (ii) the path's `{a}` and the agent
inside the signed inner body can disagree, and nothing says who wins or
what a non-`u32` id answers; (iii) the differential corpus needs a rule
for six routes. Carrying the envelope's fields in the `Authorization`
header, where the bearer token is today, with the body and path exactly
today's and the gateway composing the inner body as `agent ‖ body` (the
operator's client signs the same bytes) resolves all three and keeps the
route table identical (M2, owner Q-A).

**3c. Leader following** (`:327-335`). Resending the same frame on
`NotLeader`/`Elsewhere` is safe for every redirected kind: a `Call` by its
sequence, a `Credentialed` because a redirect answered before any apply
recorded its binding, reads trivially; `Busy` passed through, not retried;
operator kinds never redirected; `Unavailable` on a mid-request upstream
failure, never a resend (right: a resent `Credentialed` after an unknown
fate meets `Replayed`, S39). 421 past 4 to the client, as `call.rs:94-104`
does. Agreed.

**3d. The HTTP client through a gateway cannot follow a 421 today.**
`target_for` (`client/mod.rs:325-334`) re-pins `contact.node` on an
`https://` redirect under `Trust::NodeKey`, and `node_id` compares `GET /`
with the pin (`client/mod.rs:102-111`): against a gateway presenting
`gateway.key` the handshake fails and `NotTheNode` fires. §7 states the
behaviour (`:373-376`) but lists no client change: a `Trust::Gateway(key)`
arm that keeps its pin across redirects and skips the compare (M8). Since
every node's `ingress` column names its gateway under Q5(a), a redirect
through a gateway converges on the gateway, which routes again: fine.

**3e. `Create` from an empty body** (`:311-312`): the kind table says
`Operated` of `Create`; say an empty inner body is `Create::default()`
(L2). `Operator(Expiry)` at 400 against `Credential(Expiry)` at 403
(`:197`, `identity-and-authority.md` §5 row 7): one or the other (L5).

## 4. The runtime split, the crates, the client seam

**4a. tokio gateway, smol node, sans-IO codec** (`:304-308`): right, and
the only place the two meet is bytes. `vos-net` builds its endpoint on an
explicit `Runtime` (`node/net/src/quic/executor.rs:89-104`), so the
gateway's `runtime-tokio` feature unifying with `runtime-smol`
(`node/net/Cargo.toml:10`) changes nothing; say so, and that the API
endpoint in `node/host/src/api/` needs `vos-net`'s private `executor`
(`mod executor`, `quic/mod.rs:44`) exposed or copied (L6).

**4b. The crate layout inverts a dependency.** C2 moves `http.rs`, the
route table, `status` and `tls.rs`'s server half into `vos-gateway`'s
library "which the node's HTTP imports until it is deleted" (`:299-302,
:429`): the node would depend on the gateway crate, which depends on
`s4-server`, tokio and russh, until C10, which S50 may hold back past the
step. A small crate with no s4 (`vos-http`, or `vos-api` under a feature)
that both import (M6, owner Q-E). Likewise `vos-api`'s install limit must
not pull `vos-pvm-compiler` for `MAX_ELF` into the gateway and 7.13's
client facility; move the constant to `vos-wire` (L6).

**4c. The client seam** (`:365-376`): `Transport` enum behind `Client` and
`Operator`, `unix:` and `quic://` targets with a required pin, the
node-API client's own address table by key for redirects (Q5a): right,
and it leaves `Contact` and the space file alone. The order (`:381-390`)
is sound: tests and checker first, `vosx`, `vos-scale`, the suites. Step 1
"the HTTP arm through the gateway" needs M8 first.

**4d. The differential test** (`:404`): two nodes differ in `Contact`
addresses (`AgentInfo`, `NotLeader`, `Elsewhere`) and in created ids by
order; one node with both fronts, or the masking named (L11).

## Verdict

**Fix-then-implement.** Fold M1–M8 into the brief (M1, M3, M4 change C1 and
C5's content; M2 and M6 wait on Q-A and Q-E; M5, M7, M8 are a paragraph
each), L1–L15 at will, then C1. The grammar is safe, the gateway holds no
authority once C5 lands, the operator envelope is sound once it names its
node and records nonces atomically, and the migration order is right once
the HTTP client can pin a gateway.
