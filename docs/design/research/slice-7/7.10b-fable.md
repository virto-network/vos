**Verdict: fix-then-merge.** Nothing reachable over the socket, QUIC, the

## 1. Authority

**1a. One handler, four ways in, one of them privileged.** `Via`
(`node/host/src/api/mod.rs:37-47`) is set by the transport, never by the
request: the socket passes `Socket` (`api/socket.rs:164`), the endpoint
`Quic` (`api/quic.rs:217`), and only the node's own HTTP passes `Token`, and
only after `admitted` compared the bearer against `admin.token` in constant
time (`ingress.rs:81-84, 104-112`). An `Operated` header over that HTTP is
`Via::Http` and takes the signed path like the API's (`respond`,
`mod.rs:120-128`). A bare operator body on the socket or QUIC is `Malformed`
(no 88-byte prefix), as `the_socket_answers_what_http_does` and
`signed_operator_requests_run_over_quic` show for `Stats`. So the interim
("socket-only bare") is gone as the brief's §4 says, `SocketOnly` is a
retired index, and the final policy holds on every transport: a co-located
gateway on the socket holds nothing.

**1b. The envelope's checks are in the brief's order and before any copy.**
`admit` (`api/operator.rs:202-274`): the 88-byte prefix (`Malformed`), the
node (`OtherNode`), the key against the listed set (`Unauthorized`), the
expiry against the node's clock within 120 s (`Expiry { now }`); then, off
the node's thread, the decode and the signature over
`"vos/operator/1" ‖ node ‖ kind ‖ nonce ‖ expiry ‖ body` (`BadSignature`); the
inner body (`Malformed`); then for a command the nonce. The message binds
the kind, so a `Grant` signature on a `CreateAgent` body is refused
(`each_refusal_in_its_order_on_both_transports` does exactly that), and the
node, so a relay cannot carry it elsewhere (`OtherNode` before any
signature). The prefix offsets (`[..32]`, `[32..64]`, `[80..88]`) match
`Operated`'s pinned encoding (`node/api/src/operated.rs`, the envelope test
and the fuzz target's `one encoding`).

**1c. The nonce is one step, then durable, then the command.**
`Nonces::insert` (`:163-189`) checks and inserts under one `Mutex` on the
node's thread, so two copies of one request on the multiplexed socket cannot
both pass (`two_copies_at_once_run_once`); the row is then written and
synced (`PersistMode::SyncAll`) before `run`, `Unavailable` if the write
fails, and a restart refuses the replay
(`a_command_replayed_after_a_restart_is_refused`). The reads record none
(`records_nonce`, `node/api/src/lib.rs`), as Q-B decided; the bound is
65,536 shared across the listed keys, `Busy` past it with a sweep of the
expired first (`past_the_nonces_kept_a_command_is_busy`). One wrinkle: on a
failed store write the in-memory record stays, so the same nonce re-sent is
`Replayed` though its command never ran; the operator re-signs with a fresh
nonce in that case, and the `Unavailable` says so. Fine.

**1d. The operator client.** `Operator::send` (`client/operator.rs:142-151`)
signs with a random nonce, and on `Expiry { now }` learns the offset and
signs again *once, with the same nonce* (the Opus M3): a relay that holds
the first copy and forges the refusal gets the command run once between the
two. Over the API the envelope is the body; over HTTP it rides in
`Authorization: Operated <base64>` and the node's or the gateway's route
table composes `agent ‖ body` from the path (`routes.rs:93-132`), so the
path's agent is the signed one (`an operator's route, signed for another
agent` → 401 at both fronts). `repeatable = true` for a signed command
(`:164`) means a kept connection that died *after* the node ran it answers
`Replayed` (409) on the resend, not the outcome; the brief says so and the
status is unambiguous. Note only.

**1e. The gateway relays, nothing more.** `front::handle`
(`node/gateway/src/front.rs:94-125`) answers a bearer token with 401 and
never holds one; the only key it has is its QUIC client key (a transport
admission in `gateways`) and, optionally, `app.key`. `Gateway::relay`
(`routing.rs:59-111`) sends an operator kind to the one upstream whose key is
the envelope's first 32 bytes, never redirected, `OtherNode` with no node
asked otherwise (`the_gateway_follows_redirects_and_routes_operators_by_their_node`
checks `sent()` unchanged). A flipped byte of a call's arguments is the
node's `BadSignature` (`a_gateway_altering_a_signed_call_is_refused`).
`app.key` (`app.rs`) is an ordinary client key signing ordinary `Call`s and
`Query`s: it gains what any client key has, and its authority is 7.13's
registrar's invitations; one session per agent is the caller's to keep, as
the doc says.

**1f. `Trust::Gateway` in the client.** Pins the gateway's own-key TLS
(`tls.rs`, `PinnedKey` shared with `NodeKey`), is carried across redirects
(`Client::target_for`, `client/mod.rs`: `Trust::Gateway(key) =>
Trust::Gateway(*key)`), and skips `NotTheNode` (`Transport::node_id`), so a
redirect whose contact names another host fails the pin rather than
silently trusting it. `a_client_pinning_the_gateway_calls_through_it` also
shows the same key pinned *as a node* is refused. Right.

**1g. QUIC admission.** `vos_net::api::server_config` passes
`Expect::Listed(gateways.contains)` into the same `Verifier` the peers use,
ALPN `vos-api/1`, no resumption (`node/net/src/tls.rs`), on its own endpoint
and thread; an unlisted key and the peers' ALPN are refused at the handshake
(`an_unlisted_key_or_another_protocol_is_refused_at_the_handshake`). The two
framings never meet: separate ports, ALPNs and threads (L7 of the brief's
review).

**1h. The SSH port.** The authenticator takes any public key and rejects
every other credential (`ssh.rs:58-68`; s4's `Ok(None)` is a rejection,
`auth.rs:80`). The subsystem reader is `Requests::Relayed`
(`ssh.rs:127`), so a kind outside {`NodeKey`, `Time`, `AgentInfo`,
`Schema`, `Query`} is `NotRelayed` from its header, the channel closed and
no node asked (`the_relay_set_is_relayed_and_any_other_kind_refused` checks
the node's frame count). An operator kind can never enter a node this way.

## 2. Frames and DoS

**2a. Checks before allocation.** `Reader::event` (`node/api/src/frame.rs`)
reads the length and kind from six bytes, refuses `length < rest`
(`Truncated`, id 0), an unknown kind (`UnknownKind`, `0xffff` and `0x0104`
among them), a relay's outsider (`NotRelayed`), and a body past the kind's
limit (`Oversize { limit }`) *before* the body's bytes are kept; the first
failure ends the reader. The table's limits are the brief's to the byte
(`the_limits_are_the_briefs`). What arrives before the verdict is the
caller's chunk (64 KiB on the socket and the channel, at most the 1 MiB
stream window over QUIC), and a frame at the limit is accumulated in the
reader's buffer, which is the design. The proptests and the two fuzz
targets (`api_reader`: split-invariance and bounds; `operated_decode`: one
encoding) cover the right properties.

**2b. Deadlines.** A frame's deadline runs from its own first byte on the
socket (`api/socket.rs:188-192`, reset per whole frame), over QUIC
(`api/quic.rs:170-209`, the stream reset unanswered past it) and on the
channel (`ssh.rs:132-141, 202-206`); the tests drive each at 300 ms. The
HTTP server's head-and-body deadline is unchanged (`vos-http/server.rs:284,
349`). No write deadlines anywhere (their L8): a listed gateway or a local
tool that stops reading stalls its own connection's writers, which hold that
connection's in-flight places and nothing else; the gateway's HTTP writes to
a slow client hold its connection, bounded per address. Acceptable for this
step (hand-off).

**2c. In-flight caps.** Socket: `api_in_flight` by a semaphore the reader
blocks on (`socket.rs:158`), so the next frame is read only as one ends
(`a_connection_past_its_requests_in_flight_waits`); QUIC:
`max_concurrent_bidi_streams` (`quic.rs:69-71`); the channel: 16
(`ssh.rs:25, 164`, `sixteen_requests_in_flight_a_channel`). Connections:
`api_connections` at accept and after the handshake, places given back by
`Drop` guards. Queries waiting for a floor are bounded by `floor_waits`
(`queries.rs`, `FloorWait`), answered `Behind` at once past it, so slow reads
cannot hold places for long. Workflow waits already had `workflow_waits`.

**2d. Per-address and /64.** `Limits` (`node/gateway/src/limits.rs`):
connections per address at accept (`front.rs:84-89`, `Admit` before TLS),
a token bucket per address for requests, IPv6 counted by its /64 and
v4-mapped by its v4 (`counted`, `:43-51`); the buckets are bounded at 16,384
with a sweep at most once a second that first drops the full (fresh) ones,
then the idle half (`:118-130`). The channel takes a place among its
address's connections and each frame a token and, in flight, a place
(`ssh.rs:72-84, 167-179`), so one address cannot stall a node's sockets
(their H2). One gap: the 429 is decided *after* the body was read
(`front.rs:99-103`), since `vos-http` parses the whole request before the
handler; the per-address connection cap bounds that. Low (L5).

**2e. QUIC Retry and handshakes.** Every unvalidated address gets a Retry
(`quic.rs:128-131`), at most 64 handshakes are under way, each within 10 s,
and connections are counted once they shook hands (`:133-152`). The
handshake slots are takeable by any host that passed Retry (no key is needed
until the TLS verdict): 64 slots × 10 s is ~6 handshakes/s before listed
gateways are refused. The API port is meant for gateways and drivers, not
the world; worth a per-address handshake bound or a shorter timeout, and a
line in the deployment notes to firewall it. Low (L3).

**2f. The multiplexed writer task.** `multiplexed` (`node/api/src/client.rs`)
queues a whole frame on a bounded channel and one task writes them in
order; `Waiting`'s `Drop` removes the pending entry, so a request cancelled
after it queued still goes to the node (harmless: calls dedupe by sequence,
reads repeat) and its answer is dropped; cancelled while the queue is full,
nothing was queued. No half frame can reach the shared stream (their H1).
When the stream ends every waiter gets `Closed::Ended`. Right.

**2g. Large bodies: the gap that matters (M1).** `vos-http`'s server picks
the limit by the path's suffix alone (`server.rs:310-316`: any `POST` to a
path ending `/install`, an unknown one too) and buffers the whole body
before the handler sees a header (`:327-334`). At the gateway that is
64 MiB + 4 KiB per request, 64 connections per address, 1,024 in all: one
address can hold 4 GiB of the gateway's memory with no key, no signature and
no plausible header, and 16 addresses the lot. The node's own HTTP has had
the same exposure (`ingress_connections` × `MAX_ELF`), but it sat behind the
operator's token and loopback-or-TLS; the gateway is the public face. The
record leaves this open; I would not merge the gateway without a budget. The
fix is small and lives in `vos-http`, so the node's HTTP gets it too:
`Limits` gains `large: usize` (bodies past `body` in flight at once, 4 by
default) held by a semaphore in `Serve`, taken at the head and refused 503
when exhausted; and, at the gateway only, a head-time check on operator
routes: no `Authorization: Operated` of 152 bytes naming an upstream →
401/421 before the body is read, which changes nothing in status or body
(those answers never depend on the body) and keeps forgers to the budget. A
sibling budget on the node's API transports is a hand-off (L6): a listed
gateway can hold `api_in_flight` streams of 64 MiB each.

**2h. The nonce store** is bounded (65,536), swept only when full, synced
on each command: at ~65k entries the sweep is one `retain` under the mutex
on the node's thread, rare. Fine.

## 3. Fidelity

**3a. Byte for byte, on the corpus.** One route table (`routes.rs`) runs
at both fronts: paths, ids that are not `u32` (an encoded `NoAgent` on the
request routes, an empty 404 on `GET /agents/{a}` and the schema), `GET`
bodies read and unused, an empty `POST /agents` as `Create::default()`,
411/413/431 and `100 Continue` from the shared server, the `Option`'s tag
stripped for `AgentInfo`/`Schema`, a `Response`'s status from the one
`status` function, and a frame error 413 (`Oversize`), 503
(`Unavailable`) or 502. The differential test
(`gateway.rs:240-707`) sends 40 requests to the node's HTTP and through a
gateway on its socket and compares status and body with only the
legitimately varying fields masked (applied index, created id, stats,
status, `now`); each request is made fresh per front since an operator's
header is good once; `Expect` is checked on the wire. The corpus covers
every route, malformed bodies, bad ids on client and operator routes,
oversize by one, unknown paths and methods, chunked, a head too large, the
operator header missing, unreadable, expired, signed for another node,
replayed, signed for another agent, a first call per front, a read with a
body, and the six operator commands. Good coverage. What it does not cover:
an install that *succeeds* (only a malformed one; the harness installs by
the client, not the corpus), and `NotLeader`/`Elsewhere` bodies (one node:
they cannot occur), which brings 3b.

**3b. Leader following.** `relay` follows `NotLeader { leader: Some(c) }`
and `Elsewhere { replicas }` for `Call`, `Query` and `Workflow` by resending
the same frame to the upstream keyed `c.node` (or the first replica it has),
four times at most, learning a `Call`'s leader per agent on each redirect
and sending the last answer on (421) past four or with no such upstream;
`Busy` and `Unavailable` are never retried (`routing.rs:86-111`,
`upstream.rs:83-85`). The two-node test exercises `Elsewhere` (a node that
does not hold the agent), the 421 passed on by a gateway knowing one node,
and operator routing. **`NotLeader` is not separately tested** (a
single-replica agent never answers it); the arm is the same code with a
different decode, but a three-node served cluster (`tests/served`) would
close it cheaply, together with the brief's test 9 last clause, "the HTTP
client pinning the gateway and following a 421 through it", which
`a_client_pinning_the_gateway_calls_through_it` does not do (one node, no
redirect). Hand-off (L9).

**3c. The client's node-API transport** (`client/api.rs`) routes HTTP's
requests through the same table and translates the answer back with the
same `routes::answer`, so `vos`, the checker and the tests see one
interface; `transports::a_client_and_an_operator_answer_alike_over_every_transport`
runs a client and an operator over HTTP, the socket and QUIC. Redirects over
the API need a route by key (`Client::with_routes`), as the brief says.

## 4. The s4 hook (`bd3c435`)

Sound. The data path is the existing one: `Handler::data` never awaits,
`try_send`s on the channel's bounded queue (256) and fails the connection
when full (`server.rs:538-560`; the e2e `a_client_flooding_an_unread_subsystem_loses_its_connection`
proves it on a sink). `serve_subsystem` (`:632-673`) requires an
authenticated identity, takes the channel out of `pending`
(`subsystem_request`, `:459`), registers its input sender, drains russh's
own read half so it cannot fill (`:655`), and when the handler returns sends
EOF (unless the writer already shut down, tracked by `eof_sent`) and closes.
Names follow `Identifier` rules, `s4-` is reserved, duplicates are refused
at validation (`builder.rs`, the unit test). `channel_eof` and the new
`channel_close` both `forget_channel` (`:597-623`), so a close without EOF
ends the reader (`None` → `Ok(())` at EOF, `subsystem.rs:175-197`) and
frees the per-connection channel count (33, `channel_open_session`). The
override also applies to the built-in channels, which is a correction, not
a regression. Subsystem channels claim no live-session slot by design and
ride the connection's cap and `ServerLimits`; the gateway bounds the work
behind them (16 in flight, the address's places). Nothing in the hook
touches s4's own protocol.

## 5. The left-open items, and C10

- **L1 (a nonce after a clock step-back):** acceptable. The window is
  narrow (a nonce is forgotten only at a full sweep or a restart, and the
  clock must step back past the expiry while a holder of the signed request
  is listening). A cheap closer for 7.11's hardening: forget a nonce only
  past `expires + HORIZON_MS`, so a step-back within the horizon finds it
  still recorded.
- **L4 (dials under the upstream's lock): fix (M2).** `Upstream::socket`
  holds `sockets` across a 10 s `connect` (`upstream.rs:113-128`) and
  `connection` holds `quic` across the lookup and a 10 s handshake
  (`:131-164`). With one node down, every request routed to it waits for
  the dial *in turn*: the k-th waiter sees k × 10 s, up to the 300 s answer
  timeout, and reads rotate through every upstream (`next()`), so one dead
  node degrades a share of all reads to minutes, with the HTTP connections
  piling up behind. Fix: take the lock, clone an open connection or release
  the lock and dial, store under the lock after; and mark the upstream down
  for a short backoff after a failed dial so the rotation skips it. Also
  `:99-101` clears the slot on a failed request even if another task has
  since dialed a fresh connection; compare before clearing.
- **L7 (a node's closing frame error passed on a channel left open):**
  acceptable. It can only happen under version skew (the gateway validates
  with the same table), and the harm is the node closing the gateway's
  multiplexed socket, which ends that socket's other requests `Unavailable`
  once; the gateway redials.
- **L8 (write deadlines):** acceptable (2b).
- **The install-size refusal and the budget: fix (M1)** (2g).
- **C10's gating is preserved:** `admin.token` is still written by
  `Node::serve` (`node/api.rs`), `Via::Token` and `admitted` still admit a
  bare body over the node's HTTP, `tests/ingress/operator.rs` is untouched
  and green, `vos node run --tls` flags stay, `vos-http` is imported by the
  node, and the record lists the deletion under "Not done" behind S50. The
  CLI's operator commands now sign with `operator.key` instead of reading
  the token, which is the migration's order; the token's remaining users are
  tests and the bench.
- **The s4 pin** is a path dependency behind `vos-gateway`'s `ssh` feature,
  off by default and outside `just check` (`test-gateway-ssh`), with
  `--ignore-rust-version`; the rev pin waits on the branch reaching
  codeberg, as the record says. Fine for the merge; it must not reach
  master's default build, and it does not.

## 6. Code quality, where it matters

- `Kind::operator()` decides by range (`(self as u16) >> 8 == 0x02`,
  `node/api/src/lib.rs`) while the doc says "the table, not the range, is
  the rule" (`node-api.md:146-147`); a `matches!` over the eight kinds keeps
  the rule where the doc puts it (L12).
- `client/api.rs::socket_exchange` is a second frame reader (header, length
  and id by hand) beside `vos_api::Reader`; it is small and bounded by
  `MAX_ANSWER`, but it is one more place the framing lives. Fold it on the
  reader when the client is next touched.
- `api/socket.rs:171-185`: after a frame error the in-flight requests are
  detached and the connection's place given back while they run. A local
  client can exceed `api_connections × api_in_flight` by filling the slots
  and sending a bad frame, repeatedly. File-mode access only; note it in
  the module doc, or keep the place until the detached requests end (L2).
- `limits.rs` and `scale/keys.rs` and `gateway/config.rs::seed` each make a
  seed file; three copies of ten lines. Fine.
- The modules are well sized; the doc comments say what, not when.

## Findings by severity

**Medium**
- **M1. No budget for install-size bodies at the gateway (and the node's
  HTTP).** `node/http/src/server.rs:310-335`; `node/gateway/src/front.rs:77-79`.
  Any `POST` to a path ending `/install` is buffered to 64 MiB + 4 KiB before
  any header is looked at: 4 GiB per address, 64 GiB in all, with no key.
  Fix: `Limits::large` (bodies past `body` in flight, default 4) as a
  semaphore in `Serve`, taken at the head, 503 past it; at the gateway, a
  head-time 401/421 for an operator route whose `Authorization` is not an
  `Operated` of 152 bytes naming an upstream (status and body unchanged). A
  test: 5 install-size heads at once, the fifth 503 and no node asked.
- **M2. Dials under the upstream's lock serialize every request to a dead
  node.** `node/gateway/src/upstream.rs:113-128, 131-164, 99-101`. Fix as in
  §5 (dial outside the lock, a down-mark with backoff, compare before
  clearing). A test: two upstreams, one a socket nobody serves; 8 `GET /time`
  at once answer within ~1 s, not 8 × 10 s.

**Low**
- **L1** (theirs). A nonce forgotten at a sweep or restart and the clock
  stepping back past its expiry; keep forgotten nonces a horizon longer
  (`api/operator.rs:163-189, 138-158`).
- **L2.** Detached requests outlive the connection's place after a frame
  error (`api/socket.rs:171-185`); local only.
- **L3.** QUIC handshake slots (64 × 10 s, `api/quic.rs:28-30, 133`) are
  takeable by any address-validated host; a per-address bound or a shorter
  timeout, and firewall guidance for `api_listen`.
- **L4** (theirs) → M2.
- **L5.** The gateway's 429 after the body was read (`front.rs:99-103`);
  a head-time hook in `vos-http` would refuse before it.
- **L6.** The node's API transports have no budget for large bodies either:
  `api_in_flight` streams × 64 MiB from one listed gateway
  (`api/quic.rs:155-159`, `socket.rs:158`). Same semaphore as M1, on the
  node.
- **L7** (theirs). Acceptable (§5).
- **L8** (theirs). No write deadlines; acceptable (2b).
- **L9.** Test gaps: `NotLeader` through the gateway; an install that
  succeeds in the differential corpus; `Trust::Gateway` following a 421
  through a gateway (the brief's test 9, last clause).
- **L10.** `Operator::send`'s resend of a signed command on a kept
  connection's failure answers `Replayed` when the first copy ran
  (`client/operator.rs:164`); say so in the method doc.
- **L11.** The record should say `NotLeader` was not separately tested, and
  name M1 as the gate before the gateway faces the internet if it is not
  fixed here.
- **L12.** `Kind::operator()` by range against the doc's rule
  (`node/api/src/lib.rs`).

**Notes (no action)**
- The reads' replay window (120 s for `Stats`/`Status`) is Q-B's choice
  and discloses nothing the first read did not.
- The `leaders` map (`routing.rs:25, 105`) grows per agent seen in a
  redirect: bounded by real agents, since only a node's answer inserts.
- `Reader::push` drains taken bytes lazily; with a 64 MiB body pending the
  drain is a no-op, so no quadratic copy.

## Verdict

**Fix-then-merge.** Fold M1 and M2 (each a small change with a test), L11
in the record, L12 at will. The authority story holds end to end: the node
verifies every signature and runs every check, the envelope is good for one
node, one kind, once, and the gateway, the subsystem and s4's hook carry
bytes and nothing else.
