## 1. Soundness

**1a. The tagged row forms `C(c, x)` and nothing else.** The input
constraint (`recair-air/src/p2.rs:310-330`) is linear in the seven
preprocessed selectors. With leaf start and node at 1 and channel first at
−1 (`P2Mode::selectors`, `:101-114`), `act = 0` and `c_8 = c_9 = 0`
(asserted at build, `recair/src/context/mod.rs:621-630`):
`low = c + prev + b·(m − prev) − prev = c + b·(m − prev)` and
`high = m + b·(prev − m) − 0 = m + b·(prev − m)`, exactly, as polynomials;
`prev` cancels whatever the row above holds, so the row is unchained and
row order does not matter for it. What is left is `b`. The bit lookup's
multiplicity is node's selector (`:379`), 1 on a tagged row, and its
address is the zero wire's (`context/mod.rs:674`); the zero wire is
yielded once at address 0 with value `(0, 0, 0, 0)` and multiplicity
−(its uses), the tagged bits counted among them (`context/finalize.rs:101-130`,
`Circuit::bit_multiplicity`, `circuit.rs:62-64`). A `b ≠ 0` is the tuple
`(0, b, 0, 0, 0)`, which no entry cancels (the only other entries at
address 0 are the zero wire's uses, value 0, and free slots at
multiplicity 0): the logup total refuses it. So `b = 0`, the input is
`[c, m]`, and `m` is the wire pair's by the message lookups (both slots
`Message::Wire`, the wiring check refusing a free one through
`reads_whole_message`, `circuit.rs:53-59, :332-335`). The gate
`a_tagged_rows_bit_is_zero` (`tests/credential/gates.rs:326-368`) is the
right test and passes: constraints hold at `b = 1` under the node rule,
the logup refuses.

No degree, column or constraint changes: `selector · b · m` was already
the cubic term. Selectors are preprocessed, so "selector exclusivity" is
not an AIR property but the circuit's, pinned by its root; the recursion
AIR's other circuits take `selectors()`' one-hot (`trace.rs:70-76`) and
their roots are unchanged (`gates::pins`, green). The mode gates now run
the tagged composite as and against every other rule
(`tests/gates/p2_modes.rs`).

**1b. Each statement's wiring is the reference's.** Auth
(`recair/src/credential/circuit.rs:199-233`): `member = C(T(member), s)`
and `leaf = C(T(leaf), member)` as tagged rows; 32 node rows, each bit a
`guess` passed through `assert_bit` (`b·b = b`, `context/arith.rs:135`)
and used by the node row, the sibling a free message (a Merkle sibling, as
the recursion AIR's own paths), the last row's output written to the
`map_root` guess; the key `C(T(nf), s)` tagged, then a channel-first row
chained from it with `act = 1` and the `scope` wires as its message:
`nullifier = C(C(T(nf), s), scope)` with `scope` hashed, the 7.7 review's
M8 honoured. Owner: one tagged row into the `owner` guess. The reference
tests (`tests/credential/reference.rs`) compare every row's 16 input words
against `vos_wire::credentials::compress` in order at slots 0,
`u32::MAX`, `0x8000_0001` and random, check `Path::proves` on the same
path and the bit convention (`root_of`, `agent/wire/src/credentials.rs:497-507`:
bit 1 = right child ⇔ node's `b ? m : prev`), and that the wiring is
witness-independent (`the_wiring_does_not_depend_on_the_witness`). 36 and
37 permutations counted. `s` is a guess yielded by its first consumer and
used by the others (auth: the member row yields, the key row uses; owner:
yielded with no use, a free witness, as a secret must be); `scope`,
`map_root`, `nullifier`, `owner` and `binding` are guesses yielded by the
rows that compute or hash them and used by the output lanes.

**1c. The public words are bound twice.** Every word is an output at the
node layout's addresses from 3 (`recair-air/src/credential.rs:55-58`),
`kind` the zero or one wire's lane 0 (`circuit.rs:254-255`), each set by
an `assert_lane` row. The verifier mixes them after the main root and
before the relations (`final-verifier/src/masked.rs:388`) and requires
`Σ claimed + public_sum(relations) = 0` (`:396-404`) with the public sum
over `u` and the words at their addresses. `binding` is read by no gate
and is still bound by both: `an_honest_proof_of_another_statement_is_refused`
changes a binding word and sees `Logup | InteractionPow`. A word count or
kind word not the kind's is refused before any work (`check_words`,
`credential.rs:202-212`); a wrong count under `verify_with` leaves a
yielded output unused or a use unyielded, so the logup refuses it too.

**1d. The circuit is chosen by kind, never from the proof.** `verify(kind,
words, proof)` (`:195-200`) picks `preprocessed_root(kind)`; `admitted`
requires the proof's first commitment to equal it (`masked.rs:479-484`),
its log sizes and configuration the format's (`:460-470`), its tree
widths and DEEP values the pinned shape's (`check_shape`). The program id
hashes format, parameters, `[11, 11, 0]` and the root
(`recair-air/src/credential.rs:91-110`); a stale-pin test computes both
roots and both ids from the circuits (`the_pinned_programs_are_the_circuits`),
and format 44's id differs although its root is 42's. The owner-root
refusal of an auth proof and the other kind's words are tested.

**1e. Format 42.** `CONFIG` blowup 4, 43 queries, PoW 20, fold 1, last
layer 0, affine (`credential.rs:51-61`), `PARAMS` `[2, 43, 20, 1, 0, 8]`,
the registry entry equal by test. The reference shape is derived from the
built set field for field (`the_credential_reference_shape_is_the_built_sets`):
50 + 333 + 24 + 4 + 8 columns sampled once, 24 twice, 307 constraints,
11 fractions a row pair, one point doubling. The count: 43 queries at
rate 1/4 give 43 proven bits in the Johnson regime plus the 20-bit grind
less the DEEP term, 62.93; 44's 47 + 16 gives 62.92; conjectured 2 × 43 +
20 = 106 and 2 × 47 + 16 = 110. Both pinned by `the_credential_formats_count_on_their_masked_shape`
with the query term binding, and `the_parameters_are_the_least_that_clear_their_margins`
now asserts one fewer query falls below 62 for 42 and 44. 30 is in
`RETIRED` (`format.rs:610`); 44 is a constant, not in `REGISTRY`, and
`lookup(44)` is `None` by test. A relabelled 44 proof is refused under 42.
`h = 512 ≥ 2(4·2 + 43·3) = 274` and `≥ 298` for 44, both at the format's
`log_mask_rows` 9 (`mask_rows`, `recair/src/masked/mod.rs:120-144`).

**1f. The Blake2s-M31 stack.** `pcs.rs` adds the third stack beside
Blake2s and Poseidon2-M31; `Commitment::Blake2sM31` is tagged by the
stack, not the shared `Blake2sHash` type (`PcsStack::commitment`
overridden), and `from_bytes` refuses a root word at or above `p`
(`pcs.rs:198-210`). The fork's `Blake2sM31` hasher reduces its output
words and its channel draws by rejection below `2p` then reduces, so a
root's words are always below `p` and `program_id`'s `expect` holds. The
credential path itself never touches `FsChannel::mix_bytes`; prover and
verifier run one generic transcript (`prove_masked_checked` /
`replay`), so wiring consistency is by construction and the
cross-channel test (`the_prover_is_generic_over_the_channel`) proves the
same circuit on plain Blake2s trees.

**1g. `verify_masked` over two components and the one-component refusal.**
`CredentialComponents` has no `public_sums`, so both sums are blinded;
`blinds_its_sums` (`recair-air/src/masked/mod.rs:195-208`) is checked by
the prover before masking (`recair/src/masked/mod.rs:434-438`) and by the
verifier before any other admission check (`masked.rs:455-459`). The
`P2Only` test is now that refusal on both sides (`tests/circuit/masked_prover.rs`).
Right: with one blinded component the verifier's total fixes its sum
exactly, so the blinding would be the zero vector.

## 2. Zero knowledge

**2a. `h` and the masks.** Both components have `|O| = 2` (`p2` reads the
row above's S-boxes; `qm31`'s running sum reads the row above), so each
takes the format's `h = 512` and pads to `4h = 2^11` rows; 8 salt columns
a tree (248 bits), `R` of 8 columns under affine batching, R1 run on
every transcript (`Checks::ALL`) with the retry loop. The masking is
slice 6's, unchanged, applied to a set with no `h8`; the padding rows of
`p2` hold the permutation of zero and of `qm31` nothing, witness-free.

**2b. The pair is the right one, and the maximal one.** Equal public
words force one `s` (the nullifier pins it), so the only hidden variation
is the slot and its siblings: one member's leaf at two slots of one tree
(`tests/credential/leakage.rs:60-72`). Gates 2 and 3 at N = 500 passed
with margin (smallest p 6.2e-7 against 1.25e-8), 5 and 7 pass.

**2c. Gate 4 is now meaningful.** `leaked` (`leakage.rs:109-122`) looks
for two or more words of a hidden digest among every published M31
(`common::leakage::published`: samples, queried values, FRI witnesses and
last layer, claimed sums), a false positive about `C(8,2)·(10^5/2^31)^2 ≈
10^-7`; the hidden set is the secret, the nullifier's key, the member, the
leaf and every non-empty sibling; the control plants the secret into a
main-tree queried column and is found. The old byte-needle search over
postcard was vacuous because postcard varint-encodes a u32: a 31-bit
word's little-endian bytes never appear as such. **The device gate still
has it** (`tests/device/leakage.rs:123-139`, `bytes.windows(needle)` over
`postcard::to_allocvec`); it passes for the wrong reason (M1).

**2d. What gate 4 cannot see** is a leak through a linear combination,
which is what gates 2 and 3 are for; the three together are the right
shape. One note for 7.12: the proofs' *timing* is witness-independent by
construction here (one shape, branch-free path), unlike the device
kernel's.

## 4. The timing miss, and the levers for 7.12

**4a. The characterisation is honest** and the breakdown is right: at
2^11 rows the cells are small and two fixed costs dominate, the 20-bit
grind (37–43 ms mean) and the masked prover's per-prove overheads. The
owner statement costing what auth costs is structural (the floor is
`4h`, set by the queries, not the circuit) and the record says so.

**4b. The grind does not parallelise at PoW 20, and that is the biggest
lever.** The fork's `parallel_grind` (`stwo/.../simd/grind.rs:21, :102-143`)
returns the *smallest* nonce: threads take chunks of `2^GRIND_LOW_BITS =
2^20` low nonces each, and a thread that finds a solution in chunk `c`
cannot end the search until every chunk below `c` is finished. At PoW 20
the expected work is one chunk, so the wall time is about the slowest
thread's full chunk whenever the solution is not in chunk 0: with four
threads the speed-up over one is small (the measured 37–43 ms against
PoW 16's 4–5 ms says a chunk takes ~60–70 ms on one thread), and with
E-cores in the pool the search waits for an E-core's chunk, which is the
record's "8 threads slower, the grind's threads on E-cores". The
Fairphone 6 is 4 + 4 big.LITTLE, so **7.12's phone grind would measure
this artefact, not the phone**. The determinism is wanted (the seeded
byte-identity between x86 and the phone is a PG1 criterion; the verifier
accepts any nonce) and is kept by shrinking the chunk: `GRIND_LOW_BITS`
at 14–16 bounds the wait at one small chunk, the result is still the
smallest nonce, and the expected PoW-20 grind on four threads falls
toward `2^20 / 4` hashes (about 16–20 ms here), scaling on eight. The
nonce space changes, so seeded fixtures re-pin; no format or verifier
changes (M2, a fork change before the S29 measurement).

**4c. S29 on the x86 numbers.** A grind is geometric: its 95th percentile
is about 3 × its mean. At 42's measured mean the x86 p95 is already
~110–130 ms, above S29's 50 ms, and the phone's cores are slower; so with
the grind as it is, S29 picks 44 before the phone is switched on. With
M2's fix the x86 p95 would be ~50–60 ms on four threads: still at the
line, and the phone (slower per core, more thermal variance) would miss
it. **Expect 44** either way; measure it on the phone as planned, but
7.11 and 7.12 should not build anything that assumes 42's number.

**4d. The security trade-offs of each lever**, for 7.12's decision:

| lever | prove (x86, 4 thr.) | proven / conjectured | what changes | cost |
|---|---|---|---|---|
| 44: PoW 16, 47 queries (S29) | auth 40–47 ms [measured] | 62.92 / 110 | the grind 2^16; +4 queries | a forged-proof flood costs the attacker 16× less per submission (the PoW is ingress's DoS lever, pin I); proof ~+9% bytes, verify ~+9%; soundness equal, conjectured +4 bits |
| the grind's chunk (M2) | the grind ~−50% at 4 threads, more at 8 | unchanged | a fork constant; seeded fixtures re-pin | none |
| `h = 256` (7.14's option 2: drop the ×2 margin in `mask_rows`) | the masked prove about halves (floors 2^10; columns 2^11, composition 2^13) | unchanged (prover-side) | new pins (roots unchanged, log sizes `[10, 10]`, program ids change) | the R1 retry rate must be measured (a retry is a full re-prove); the ZK guarantee is R1 per transcript, not the margin |
| blowup 8 with 29 queries | about the same cells as `h = 256` at blowup 4 (revealed 190 → `h = 256`); fewer queries: bytes ~−30%, verify cheaper | 29 × 1.5 + 20 ≈ 63.5 − ε / 107 | a new format number, its own count on its shape | none in security; more work at 7.12 (recount, re-pin); the proof stays ~140 KB |
| the per-prove overheads (7.14 §5.1) | several ms of the 35–40: twiddles for 2^15 and `MaskLayout` per prove (`recair/src/masked/mod.rs:420, :453`), the BLAKE2b witness digest over ~2.7 MB, R1 3.4–4 ms | unchanged | caching | none |

**Recommendation for 7.12:** M2 first (it changes what the phone
measures), then measure 42 and 44 as S29 says; take 44 unless the fixed
grind's phone p95 clears 50 ms, which I do not expect. Take `h = 256`
only if PG1 needs it after 44 (it costs a re-pin and a retry-rate
measurement; its win is ~15–20 ms on x86, ~3× that on the phone).
Blowup 8 is the lever for *bytes* (ingress's 512 KiB cap is far; the
gateway's and the phone's radio are nearer), not time: defer unless 7.12
sees a transport cost. The owner's 30 ms target cannot be met by any
lever that keeps one shape for both kinds (Q1).

## 5. Code quality and feature gating

Where it matters it is good: the circuits are one readable file with the
statement, the forger's knob and the wiring apart; the prover module is
generic over channel and format with the pinned entry points thin on top;
the verifier's constants are pinned under stale-fixture tests and
`verify_with` is documented as the circuit-generic step ingress must not
call. The three-mode composite is the right call against a new selector
column (no AIR change, every other circuit's root unchanged), and
`selectors()` keeps the one place that knows it. `forge`, `prove_forced`
under `seeded-masks`; `credential-bytes` is dropped by the kit; postcard
canonical decode; `check-no-leaks` unchanged. Small things:
`Circuit::log_sizes` panics on an `h8`-less circuit (`ilog2(0)`,
`circuit.rs:229-231`) and relies on the documented "every caller checks
the wiring first" (L1); `FsChannel::mix_bytes` for `Blake2sM31Channel`
mixes one u32 a byte (`pcs.rs:81-90`), harmless here and 32× the hashing
of a boundary mix if format 43 or 37 ever uses it (L2); the device
leakage gate's dead needle (M1).

## Findings by severity

**Medium**
- **M1. The device hidden-state gate is vacuous.**
  `pvm/proof/recair/tests/device/leakage.rs:123-139`: an 8-byte
  little-endian needle searched in postcard bytes, which varint-encode
  every M31, so the search cannot match and the gate passes for the wrong
  reason; the 7.10 record flags it. Fix: the credential gate's method
  (`common::leakage::published` and a `leaked`-style word search with a
  planted control), in this branch (fifteen lines against a harness that
  now exists) or as the first thing in 7.16; a gate that cannot fail is
  worse than none in `just test-proof`.
- **M2. The grind's chunking defeats its parallelism at PoW 20** (§4b):
  the fork's `GRIND_LOW_BITS = 20` (`crates/stwo/src/prover/backend/simd/grind.rs:21`,
  `parallel_grind` `:102-143`). Not 7.10's code, but 7.12's S29
  measurement and PG1 depend on it, and the record's thread observations
  are its symptom. Fix in the fork before the phone bench: a smaller
  chunk (14–16 bits), the smallest-nonce rule kept, seeded fixtures
  re-pinned; verify on x86 that the 4- and 8-thread PoW-20 means fall and
  order correctly. State in the 7.12 entry which grind the numbers were
  taken on.

**Low**
- **L1.** `Circuit::log_sizes` (`recair/src/circuit.rs:229-231`) panics on
  a two-component circuit; a `debug_assert!(!self.h8.is_empty())` with the
  documented reason, or an `Option`, is cheaper than the comment.
- **L2.** `FsChannel::mix_bytes` for `Blake2sM31Channel` (`pcs.rs:81-90`)
  mixes a u32 a byte; pack four bytes a word before format 37/43 uses it
  (a transcript decision that must be made before, not after, a format
  pins it). Hand-off to 7.16.
- **L3.** `verify_with` is `pub` and takes any root; ingress must call
  `verify`, and pin I's fuzz target should be `verify_bytes`/`verify`,
  never `verify_with`. Hand-off to 7.11. Also for 7.11: in Stwo's order
  the composition check (`masked.rs:428, :489`) runs before the 20-bit
  PoW check inside `verify_values`; pin I's "wrong PoW refused in under
  1 ms" should be measured, not assumed (the whole verify is ~2 ms, so it
  should hold).
- **L4.** Gate gaps: a tagged row with a free message refused by
  `check_wiring_without_h8`; `verify_with` with a wrong word count
  (`Logup`); both one case each.
- **L5.** `examples/credential_timing.rs:75-93` reports the grind's mean,
  median, least and most; S29 is a 95th percentile. Add the p95 of a few
  hundred grinds and run it at 1, 4 and 8 threads, so 7.12 measures what
  the decision names (and sees M2's effect).
- **L6.** The record's "Verification 1.9–2.2 ms on 4 threads" undersells
  pin I: the no_std verifier is single-threaded, so this *is* the one-core
  number; say so.

**Notes (no action)**
- The tagged composite relies on the selectors being preprocessed; a
  future AIR that constrains selectors one-hot would have to exempt it,
  and `recursion-air.md` §1.3 now records why. Fine.
- `prev` cancelling exactly means a tagged row at row 0 (offset −1 the
  last row) is fine; row order still matters for the node chain and the
  nullifier's channel-first row, which the circuit pins.
- A proof's `kind` word is redundant with the kind-chosen root; keeping
  both costs one lane and makes the words self-describing for the log.
- Owner's cost equals auth's at every lever that keeps one shape; a
  smaller owner floor needs its own `h`, i.e. its own format number, not
  worth it for 30 ms.

## Owner questions

- **Q1. The owner statement's 30 ms gate** (`slice-7-mobile.md` §7.10,
  §7.12's 150 ms on the phone). Owner pays the shared floor (74–84 ms at

## Verdict

**Accept.** The AIR's new row is sound by the algebra and by the gates;
the statements are the reference's; the format is counted on what was
built; the verifier pins what pin I says and reads nothing else from the
proof; the masking hides what equal public words leave hidden. M1 and M2
are not defects in this branch's code but should land before 7.12
measures anything (M1 anywhere, M2 in the fork); L1–L6 at will; Q1–Q3
for the owner.
