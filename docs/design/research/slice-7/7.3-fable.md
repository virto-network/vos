# 7.3 review: reads, reports and the worker's edges

Branch `s7/7.3`, `61c0950e..ce14c99f`, against pin D′ (with S34), §7.3,
`simplify.md` C9–C11, slice 6's M3, M4, L6 and item 68. Read-only; no
test added (the one file allowed is this one).

## What holds

- **Every replicated row is written where it must be.** `reading` is a
  refine write (the ask, `invocation.rs:646-650`; the representative's
  `stored`, `closes.rs:222-227`), `every_window` a refine `Admin` write
  (`admin.rs:79-85`), `cut_mark` apply's (`apply.rs:139-157`), all three
  system rows of the agent's state: committed with the result, in the
  JAM witness, in snapshots. `attested` is the node's apply
  (`node/host/src/prover.rs:130-191`), a `TreeRow` under the agent's
  epoch prefix, so `store/read.rs`'s whole-partition export carries it;
  computed from the entry's steps and the pre-entry snapshot alone, so
  the same bytes on every replica. The testkit mirrors each
  (`agent/testkit/src/closes.rs`, `at_cut.rs`), and the checker model's
  `cuts()` states the new rule (`tests/cuts/model.rs:443-492`).
- **C9 is sound and `CUT_KEEP = READ_WINDOWS = 2` is exactly enough.**
  A read asked in `w` is ended `NotClosed` by its due at
  `B_{w+2}` (`workflows.rs:331`); `cut(w)` and `closed(w)` go only with
  the recording of `cut(w+2)`, which no result timed before `B_{w+2}`
  can make. `Finish::write` keeps two cut roots, so a new leader still
  reports the one window it can serve. A read fails only when its
  report misses the representative's cut (`B_w + D` on the shifted
  clock, `WindowClock::representative`), which is the design's `D`, not
  7.3's. Slow proving never touches a read's rows: the attest records
  are pruned by `MaxRootAge`, not `CUT_KEEP`.
- **Reads and reports cannot half-cut a window.** `Reads` is read before
  the steps (`apply.rs:99-103`), so a read a result makes never cuts a
  window that result crosses, and a read in `w` lives in a result timed
  in `w`, before the result that crosses `B_w`. The leader's marker
  (`cut.rs:39-48`) gates on the same row, so an idle agent gets none
  (`an_idle_agent_appends_no_marker`).
- **C11 and S34.** The anchor row is written in the cut's finishing
  commit, from the committed log, for a window with a path; the guard
  compares rows as before. The exception is a late builder (L1).
- **M3 exactly-once.** Jobs keyed by statement id; `proven` first-wins;
  a snapshot-installed replica scans the records it was handed
  (`a_snapshot_installed_replica_proves_a_queued_statement`); the
  deposed node's proof reaches the leader (`PeerMessage::Proved`,
  admitted only from a replica, `dispatch.rs:70`). "At most the one in
  flight proved twice" holds. Pruning by `MaxRootAge` is done in apply
  on a boundary crossing, deterministic, O(records of the agent).
- **Privacy.** The attest records carry the witness and served rows for
  up to 24 h on the agent's replicas and in their snapshots: the same
  carriers as the log held before, longer-lived than compaction.
  `SECURITY.md:445` names the row; the audit ran clean over 443
  carriers. A refused or dead statement keeps its witness the full 24 h
  (no `Proven` ever strips it); acceptable, bounded.
- **Item 68** is deterministic (the agent's own code on both hosts,
  witness-covered) and not a DoS: no input writes the rows it reads
  (`reported`, `closed(w)`, `close_mark`, `reports(from)`, `reading`),
  so only corruption or a bug reaches it, and the quarantine key is the
  row's own key (rewritten, not accumulated).
- **The opt-in** goes through `Inner::admin` like `Install` and
  `SetRole`: operator-only, replicated as an `Admin` step, witnessed on
  JAM, documented (`operations.md:84-92`, `proving.md:829-834`).

## Medium

### M1. A kernel asked for past `patience` poisons the worker for that kernel until restart

`node/prover/src/worker.rs:417-435, 439-442`. `statement()` turns a
kernel absent for `patience` (60 s) into `NO_PROGRAM` and **caches it in
`programs`** for good. Every later record naming that kernel, for every
agent on the node, gets a statement with the wrong program id, so a
wrong statement id. If the kernel then arrives, `prove()` proves the real
attest under the bogus id, `record()` writes `proven(window, bogus_id)`
and apply strips the **real** record's witness (the digest in
`Input::Proven` is the record's), and `submit()` hands the venue a
statement of program `NO_PROGRAM`, refused. The true statement is never
proved by this node; a replica that joins later holds a witness-less
record and cannot prove it either (L2).

Scenario: a snapshot-installed replica with a long blob fetch queue, or a
replica partitioned from the others for a minute while a new package's
kernel is not yet local; the checker loop partitions nodes longer than
that. `a_kernel_is_held_and_one_never_fetched_refused` runs with
`patience: ZERO` and never lets the kernel arrive, so it does not see
this.

Fix (simplest, sound): drop `NO_PROGRAM` and the refusal-by-patience.
`scan()` leaves a record whose kernel is not here in `unread` (it already
does), `prove()` returns `false` for it (it already does), and an alert
at `patience` says the kernel never came; the record ages out with
`MaxRootAge`. M4(b)'s complaints (the scan stalling, the job picked every
step) are already answered by `unread` and `tried`. If the refusal is
wanted, never insert the lost case into `programs`, and refuse in
`prove()` only, keeping `job.statement` the true one.

## Low

### L1. C11 makes the anchor row's existence depend on how late a replica builds the cut

`node/host/src/roots/cuts.rs:339, 386-420`. `closing()` reads the
window's asks from the live snapshot `at`; `stored` deletes a sender's
ask of `w` once it reports `w+3` (`closes.rs:206-219`). A replica whose
builder reaches `cut(w)` after that finds no asks, so no paths, so (new
with C11) **no `anchor(w)` row**; before 7.3 it wrote the row with the
right root and only lacked paths. In the guard it now abstains
(`anchor.rs:365-370`, `None => {}`); anchoring in window order needs a
quorum of on-time builders per window, else the leader asks every 2 s
until the window ages. Fix: take the asks at the cut, deterministically:
the live `asked` prefix plus the undo rows under `keys::undos(w)` whose
row is in the asked prefix (`undo()` keeps every committed row a later
write deleted while the cut was pending), so every builder writes the
same closing and the same anchor row however late.

### L2. The witness is stripped at `Proven` before any node but the prover holds the proof

`node/host/src/prover.rs:141-156`, `leader/proven.rs:26-41`. A proved
statement's record loses its witness on every replica as soon as the
leader records `Proven`, but the proof blob lives only in the prover's
store until `submit()` fetches it. If the prover dies for good, a replica
whose job was made after `Proven` (snapshot-installed, or joined later)
goes `unfetched` → `Queued` → `prove()` on an empty witness →
`REFUSED_RERUN`, logged as "a record's re-run is not its statement"
(`worker.rs:531-543, 593-596`): a wrong diagnosis of a right statement.
Fix: in `Leader::proofs()` propose `Input::Proven` only once this node
holds the proof blob (fetching it otherwise), so a recorded proof has two
holders whenever the prover is remote; and in `prove()` refuse a
witness-less attest with its own reason instead of running the kernel.

### L3. A read at the representative itself can regress `reading`

`agent/default/src/refine/invocation.rs:646-650`,
`agent/testkit/src/invocation/at_cut.rs:76-78`. The ask writes
`reading = window` whenever it differs; `stored` writes it only when
greater. The representative accepts a report of `open + 1` (an agent
leading by more than `L − D`, `a_leading_clock_reports_its_next_window_apart`);
a read at the representative in `open` then writes `reading = open`, and
`Reads::cuts` (`apply.rs:391-398`) never cuts `open + 1`: the leading
agent's read ends `NotClosed`, with no re-cut to save it. Fix: the ask
writes only when `reading < window`, as `stored` does.

### L4. The cut rule is stated three times

`apply.rs:391-398` (`Reads::cuts`), `leader/cut.rs:39-48` (`cut_due`),
`tests/cuts/model.rs:443-492`. The leader's `reading >= window(mark)`
must stay equal to apply's `reading >= first && window(mark) == first`;
they agree today. One `pub fn` in `vos_wire::apply` taking
`(clock, mark, time, every, reading)` and called by the leader with
`time = boundary(window(mark))` removes the drift.

### L5. The opt-in at the representative anchors nothing of its own

`cuts.rs:339`, `closes.rs:184-195` (`from == base.agent` stores nothing).
An issuer installed on the founder's agent (the representative) gets
`every_window` cuts, but a window no other agent reported has no paths
and so no anchor row. Either document that the issuer must not be the
representative, or write the anchor row when the representative's own
`every_window` is set (`!paths.is_empty() || every_window`), which is
C11's intent for an issuer.

### L6. The opt-in has no operator surface

`operations.md:90` points the operator at `Node::report_every_window`, a
Rust method; no `vos`/`vosx` verb exists. One line in the CLI, or the
runbook saying it is a node-API call for now.

## Info

- `hold_kernels` (`worker.rs:445-458`) keeps the held set in memory: a
  crash between a job finishing and the next step leaks that kernel's
  `NODE_AGENT` pin for good. A listing of the node's own pins at `open`
  would let it unpin the unwanted.
- `prune` (`worker.rs:347`) removes the jobs of any agent not in `runs`
  now; a transient absence during a placement change drops a `Proved`
  job and its pin, and the record recreates it `Queued`. Harmless, a
  re-proof.
- L6(b) covers `Node::stop` (`open.rs:204-210`); a SIGKILL or power loss
  mid-proof still counts an attempt. The docs say "the node's own stop",
  which is right.
- `attested()`'s prune runs only when a result crosses a boundary, and an
  idle agent gets no marker now: its aged records stay until its next
  result. Bounded by activity.
- `stored` with a quarantined `reports(from)` treats the report as the
  sender's first and never deletes its older rows (at most three): a
  one-off leak per event, by design "the next report writes the row
  afresh".
- `PeerMessage::Proved` carries a hash the leader records unverified;
  replicas are the trust domain, and `unfetched` recovers from a hash
  whose blob never comes.
- The retry wait is now capped (`RETRY_MAX`), closing 7.2's info item.

## Simplicity

The design is simpler than slice 6's: one cut per read-window, no re-cut
chain, no `serving`/`moved`, no `PROVER_HOLD` tying compaction to the
prover, no watermark, no `lost`. The +31 lines are honest: C9 removed
132, C10/C11 added a conditional cut rule (three rows and `Reads`, L4's
triplication), and the worker's edges added more than they removed. The
worker now carries eight in-memory maps (`programs`, `missing`,
`kernels`, `read`, `unread`, `asked`, `unfetched`, `retries`). Concrete
cuts: M1 removes `missing` and `NO_PROGRAM`; `read` and `unread` can go
in favour of `jobs.get` as the dedup plus one per-agent window
watermark (a rootless record becoming a finished job instead of a
warn-and-skip keeps the table the single source); `asked` and
`unfetched` are one `HashMap<StatementId, Fetch>`. The step is not a
state machine: `reading`, `every_window` and `cut_mark` are three
monotone rows, and the cut rule is one predicate once L4 lands.

## Verdict

**Fix-then-merge.** M1 before merge (a realistic fetch delay poisons a
kernel node-wide and strips a real record's witness). L1, L2 and L3 are
small and worth folding now, L3 a one-comparison change; L4–L6 and the
Info items may ride the next pass.
